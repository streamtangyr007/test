# 学习路线图

> 原则：**读一章 → 让 Claude 讲解 → 写最小实现 + 测试 → 在 sandbox 里看到效果 → 勾选进度**。
> 不追求一次做完美，每个模块先做"能跑的学习版"，以后需要时再升级。

教材以《游戏引擎架构》第3版（Jason Gregory）为主线，章节号均指该版本；第2版中文版章节略有不同，按标题对照即可。

---

## 阶段 0：打地基（第1–3章）

**读**：第1章 导论（重点 1.6 运行时引擎架构）、第2章 专业工具、第3章 游戏软件工程基础。

- [x] CMake 项目结构、编译警告、`.clang-format`
- [x] 基础类型 `types.h`、断言 `ENGINE_ASSERT`、日志 `engine::log`
- [x] 零依赖单元测试框架
- [ ] 自己动手：用调试器（gdb/lldb/VS）单步跑一遍 `engine_tests`
- [ ] 自己动手：给日志加上时间戳，或加一个写文件的 sink

**要理解的概念**：编译/链接模型、头文件依赖、调试版与发布版的区别、断言与错误处理的区别。

## 阶段 1：核心系统（第6、8、10章）✅ 骨架已完成

- [x] 栈分配器（第6.2节）
- [x] 池分配器（第6.2节）
- [x] 固定步长游戏循环（第8章）
- [x] 命令注册表 / 开发者控制台（第10章）
- [ ] 进阶：双缓冲帧分配器（每帧清空的 StackAllocator ×2）
- [ ] 进阶：内存统计——每个分配器上报已用/峰值，并注册 `mem` 控制台命令
- [ ] 进阶：简易性能剖析器 `ENGINE_PROFILE_SCOPE("name")`（第10章 游戏内性能剖析）

**要理解的概念**：为什么游戏要避免频繁 `new/delete`（碎片、不可预测的耗时）；
固定步长 vs 可变步长；"死亡螺旋"是什么。

## 阶段 2：数学库（第5章）

- [ ] `Vec2/Vec3/Vec4`：加减、点积、叉积、长度、归一化
- [ ] `Mat4`：乘法、转置、逆、平移/旋转/缩放、透视/正交投影、`lookAt`
- [ ] `Quat`：轴角构造、乘法、旋转向量、`slerp`
- [ ] 每个函数都有测试（和手算值 / 已知恒等式对比）
- 可选：学完后切换到 [glm](https://github.com/g-truc/glm) 或保留自己的实现

**要理解的概念**：左手/右手坐标系、行主序/列主序、为什么旋转用四元数（万向锁）。
**推荐配套**：《3D数学基础：图形和游戏开发》、3Blue1Brown《线性代数的本质》视频。

## 阶段 3：平台层与输入（第9章 + 第1.6节平台无关层）

- [ ] 引入 **SDL3**（CMake FetchContent）：创建窗口、事件循环
- [ ] `platform::Window`、`platform::Input` 抽象接口，SDL 只出现在 `platform/` 的实现里
- [ ] 输入：按键状态（按下/保持/抬起）、鼠标、手柄；"动作映射"（`Jump` → 空格/A 键）
- [ ] 保持无头模式：`--headless` 时使用空实现（Null Window）

**要理解的概念**：为什么要抽象平台层；轮询 vs 事件驱动输入。

## 阶段 4：渲染入门（第11章）

- [ ] 选定图形 API：推荐 **OpenGL 3.3 Core**（配合 LearnOpenGL 教程最顺），以后再抽象成 RHI 升级到 Vulkan/D3D12
- [ ] 画三角形 → 带纹理的四边形 → 2D 精灵批处理（先做 2D，最快看到成果）
- [ ] 相机（正交/透视）、变换组件 `Transform` + `SpriteRenderer` 组件接入 ECS
- [ ] 截图命令 `screenshot out.png` —— 让 AI 也能"看见"渲染结果
- [ ] 3D：网格、深度缓冲、Phong/Blinn-Phong 光照

**要理解的概念**：渲染管线各阶段、顶点/片元着色器、GPU 与 CPU 的同步。
**推荐配套**：LearnOpenGL（有中文版）、《Real-Time Rendering》。

## 阶段 5：资源管理（第7章）

- [ ] 虚拟文件系统：统一路径 `assets://textures/player.png`
- [ ] 资源句柄 + 引用计数 + 缓存（同一文件只加载一次）
- [ ] 文本格式场景文件（JSON，推荐 nlohmann/json）：保存/加载整个 ECS World
- [ ] 热重载：文件变化时重新加载纹理/着色器

**要理解的概念**：离线资产管线 vs 运行时加载；为什么资源用句柄而不是裸指针。

## 阶段 6：游戏性基础（第15–16章）

- [ ] 事件/消息系统（发布-订阅）
- [ ] 组件反射：为组件声明字段元数据 → 自动序列化、自动生成编辑器 UI、自动告诉 AI 有哪些字段
- [ ] 脚本：嵌入 **Lua**（sol2）——游戏逻辑可以不重新编译
- [ ] 做一个小游戏：打砖块 / 太空射击，验证整个引擎

**要理解的概念**：以对象为中心 vs 以属性为中心的对象模型；数据驱动；更新顺序与依赖。

## 阶段 7：碰撞与物理（第13章）

- [ ] 2D：AABB、圆形碰撞检测 + 简单响应
- [ ] 宽相位（均匀网格 / 动态 AABB 树）+ 窄相位
- [ ] 刚体积分（半隐式欧拉），利用固定步长
- 可选：之后接入 Box2D / Jolt Physics

## 阶段 8：动画（第12章）

- [ ] 精灵帧动画（2D）
- [ ] 骨骼、姿势、蒙皮（3D），动画混合

## 阶段 9：音频（第14章）

- [ ] 接入 miniaudio：播放音效、音乐、音量分组

## 阶段 10：工具与编辑器（第2、10章）

- [ ] **Dear ImGui** 调试界面：实体列表、组件检视器、控制台窗口、性能图表
- [ ] 场景编辑：选择、移动实体，保存场景
- [ ] **AI 接入**：把命令注册表暴露为 MCP 服务器，让 Claude 直接查询/修改运行中的引擎（见 `03-ai-workflow.md`）

## 阶段 11：进阶（第4章 并发 + 性能）

- [ ] 任务系统（job system）、多线程更新
- [ ] 数据导向设计（DOD）与 archetype ECS
- [ ] 渲染抽象层（RHI）→ Vulkan

## 建议节奏

| 阶段 | 预估时间（业余） | 可见成果 |
|---|---|---|
| 0–1 | 1–2 周 | 测试全绿、控制台可交互 |
| 2 | 1 周 | 数学库 + 测试 |
| 3–4 | 3–4 周 | **窗口里会动的精灵** |
| 5–6 | 3–4 周 | 从 JSON 加载关卡的小游戏 |
| 7–10 | 按兴趣选 | 物理、动画、声音、编辑器 |

最容易放弃的时刻在"还没看到画面"的阶段。如果动力不足，可以先跳到阶段 3–4 画出东西，再回头补数学库。
