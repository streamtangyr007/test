# 引擎架构

## 1. 书中的运行时分层（《游戏引擎架构》第1.6节）

Gregory 把运行时引擎画成一座"塔"，**每层只依赖它下面的层**：

```
┌──────────────────────────────────────────────────────┐
│ 游戏专属子系统 (Game-Specific)   武器、AI、关卡逻辑…      │  ← 你的游戏
├──────────────────────────────────────────────────────┤
│ 游戏性基础 (Gameplay Foundations)                        │  ← ecs/  (第15–16章)
│   游戏对象模型、事件、脚本、世界加载                         │
├───────────┬───────────┬───────────┬──────────┬───────┤
│ 渲染       │ 动画       │ 碰撞/物理  │ 音频      │ 输入   │  (第9、11–14章)
├───────────┴───────────┴───────────┴──────────┴───────┤
│ 资源管理 (Resources)   资产加载、引用计数、热重载          │  (第7章)
├──────────────────────────────────────────────────────┤
│ 核心系统 (Core Systems)                                 │  ← core/ memory/ tools/
│   内存分配、断言、日志、数学库、字符串、容器、配置、并发     │  (第3–6、8、10章)
├──────────────────────────────────────────────────────┤
│ 平台无关层 (Platform Independence Layer)                 │  (计划：platform/)
│   窗口、文件系统、线程、计时器 的统一封装                    │
├──────────────────────────────────────────────────────┤
│ 第三方 SDK / 操作系统 / 驱动 / 硬件                        │
└──────────────────────────────────────────────────────┘
        工具链(离线)：资产管线、编辑器、构建系统 —— 与运行时分开
```

## 2. 本仓库的模块映射

| 目录 | 层 | 状态 |
|---|---|---|
| `engine/core/` | 核心系统：类型、断言、日志、游戏循环 | ✅ |
| `engine/memory/` | 核心系统：栈分配器、池分配器 | ✅ |
| `engine/tools/` | 调试工具：命令注册表 / 控制台 | ✅ |
| `engine/ecs/` | 游戏性基础：实体-组件-系统 | ✅（学习版） |
| `engine/math/` | 核心系统：向量/矩阵/四元数 | ⏳ M2 |
| `engine/platform/` | 平台无关层：窗口、输入、文件 | ⏳ M3 |
| `engine/resource/` | 资源管理 | ⏳ M5 |
| `engine/render/` | 渲染 | ⏳ M4 |
| `engine/physics/` | 碰撞与刚体 | ⏳ M7 |
| `engine/audio/` | 音频 | ⏳ M9 |

## 3. 依赖规则

- 下层**不能** `#include` 上层。例：`memory/` 不能知道 `ecs/` 的存在。
- 横向同层模块之间尽量不直接依赖（渲染不直接调用物理），由上层（游戏性层/系统）组装。
- 平台相关代码只能出现在 `platform/`（以及它选用的第三方库里），其他模块只看平台无关接口。

## 4. 贯穿全局的设计决策

| 决策 | 理由 | 书中出处 |
|---|---|---|
| 固定步长模拟 + 插值渲染 | 确定性、可回放、可测试 | 第8章 |
| 自定义分配器而非到处 `new` | 可控、可统计、缓存友好 | 第6章 |
| 以组件/数据为中心的对象模型（ECS） | 组合优于继承，数据紧凑 | 第16章 |
| 引擎可无头运行 | CI、服务器、AI 自动验证 | — |
| 所有调试操作走命令注册表 | 人、脚本、AI 共用一套接口 | 第10章 |
| 数据驱动（场景/配置用文本格式） | 可读、可 diff、AI 可直接生成/修改 | 第7、16章 |

## 5. 每帧执行顺序（当前 + 规划）

```
GameLoop::tick(realDt)
 ├─ platform.pollEvents()            (M3) 输入、窗口事件
 ├─ while (accumulator >= fixedDt)
 │    └─ fixedUpdate(fixedDt)        逻辑系统、物理(M7)、动画(M8)
 ├─ update(realDt)                   相机、UI、调试控制台
 └─ render(alpha)                    (M4) 按 alpha 插值后提交绘制
```
