# 用 Claude 开发引擎的工作流

这里的"兼容 AI 开发模式"分两层：

1. **开发期 AI**：用 Claude Code 帮你写代码、写测试、讲解概念、审查设计（现在就能用）。
2. **引擎本身对 AI 友好**：引擎的结构让 AI 能读懂、能运行、能验证、能操作（本仓库从第一天就这样设计）。

（第三层——游戏**运行时**的 AI，比如行为树、寻路、LLM 驱动的 NPC——属于游戏性系统，放在阶段 6 之后再做。）

---

## 一、日常协作流程

### 1. 每次会话只做一件小事
好的任务粒度："实现 `Vec3` 及其测试"、"给池分配器加内存统计命令"。
不好的粒度："实现渲染器"。大任务先让 Claude 拆解：

> 读 docs/01-roadmap.md 的阶段 4。把"画三角形 → 精灵批处理"拆成 5–8 个可以各自提交的小步骤，
> 每步说明要改哪些文件、怎么验证。先别写代码。

### 2. 先理解，再动手（学习模式）
> 我正在读《游戏引擎架构》第6章内存管理。请结合本仓库的 `pool_allocator.h`，
> 用中文解释空闲链表是怎么"嵌入"在空闲块里的，画一个内存布局示意图。然后给我出 3 道思考题。

### 3. 测试即规格
> 我想实现一个双缓冲帧分配器（第6章）。请先只写 `tests/test_memory.cpp` 里的测试用例，
> 描述它应有的行为，我确认后再实现。

### 4. 自己写，让 Claude 审
学习最有效的方式是自己先写一版：
> 我自己写了 `engine/math/vec3.h`，请审查：正确性、边界情况（零向量归一化）、性能、
> 和书中第5章的说法是否一致。只指出问题，不要直接改。

### 5. 每步收尾
> 运行全部测试；更新 docs/01-roadmap.md 的勾选；用中文写一个清晰的 commit message 并提交。

## 二、提示词模板

**实现新模块**
```
任务：实现 <模块>，对应《游戏引擎架构》第 X 章 <小节>。
要求：
- 遵守 CLAUDE.md 中的架构规则与代码约定
- 先写测试 tests/test_<模块>.cpp，再写实现
- 头文件注释里说明：书中方案 / 我们的简化 / 以后如何升级
- 如需新增控制台命令，一并注册
完成后运行测试，并用中文总结我需要理解的 3 个关键点。
```

**调试**
```
<现象>，复现步骤：<命令>。
请先定位根因并解释原因，再给出最小修复，并补一个能复现该 bug 的测试。
```

**设计讨论**
```
我要在 <方案A> 和 <方案B> 之间选择（例如：OpenGL vs Vulkan 起步 / 自研 ECS vs EnTT）。
考虑到我是初学者、目标是 <目标>，给我一个推荐，并说明主要理由和以后切换的代价。
```

## 三、让引擎对 AI 友好的设计原则

AI 最怕两件事："看不见结果"和"无法验证"。下面这些原则都是为了解决这两点，而且对人类开发同样有益。

| 原则 | 在本仓库中的体现 | 对 AI 的价值 |
|---|---|---|
| **可无头运行** | `GameLoop::runHeadless`，逻辑不依赖窗口 | Claude 能在云端/CI 中直接跑游戏逻辑 |
| **确定性** | 固定步长 `fixedUpdate` | 同样输入 → 同样结果，测试可断言 |
| **测试驱动** | `tests/`，`engine_tests <过滤>` | AI 改完立刻知道对不对 |
| **命令化接口** | `tools::CommandRegistry` | 人、脚本、AI 共用同一套操作入口 |
| **结构化输出** | `CommandResult`，可替换的日志 sink | AI 读结果不用猜文本格式 |
| **数据驱动**（规划） | 场景/配置用 JSON | AI 可以直接生成和修改关卡 |
| **反射/元数据**（规划） | 组件字段描述 | AI 能"发现"有哪些组件、字段 |
| **截图命令**（规划） | `screenshot out.png` | 多模态模型能"看"渲染结果 |
| **清晰的模块边界** | 分层 + CLAUDE.md 规则 | AI 修改范围可控，不易改坏别处 |
| **文档即上下文** | `CLAUDE.md`、`docs/` | 每次新会话 Claude 都能快速进入状态 |

### 未来：把引擎接入 Claude（MCP）

阶段 10 的目标：写一个小型 MCP 服务器（可以是引擎内的 TCP/stdio 端点），把 `CommandRegistry`
里的每个命令暴露成一个工具。之后你可以对 Claude 说：

> 在运行中的游戏里生成 20 个敌人，跑 300 帧，然后截图，告诉我碰撞有没有穿透。

Claude 会调用 `spawn`、`step`、`screenshot` 等命令，自己检查结果。
因为这些命令现在就已经是返回结构化结果的普通函数，届时只需要加一层传输协议，不用重构引擎。

## 四、让 Claude 保持"记忆"

- **CLAUDE.md**：项目规则、构建命令、约定。规则变了就更新它。
- **docs/01-roadmap.md**：进度看板。每完成一步就勾选，Claude 开新会话时读它就知道做到哪了。
- **commit message**：写清楚"为什么"，未来的你和 Claude 都靠它理解历史。
- 发现 Claude 反复犯同一个错误 → 把正确做法写进 CLAUDE.md。
